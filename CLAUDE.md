# Project guide for Claude Code (commander)

## What this project is

zcrew turns Claude Code or Codex into a commander that plans, delegates to ZCode (GLM) workers over MCP, reviews their diffs and runs the tests itself. It ships as a Windows installer plus a stdlib-only Python CLI (`zcrew`), and includes read-only views of worker activity (`zcrew runs/show/watch` and `zcrew dashboard`).

## Architecture

- `scripts/zcrew.py` — CLI entry; dispatches to sibling modules loaded by path (`importlib`), not as a package.
- `scripts/commander.py` — `enable/disable/status/config`; writes the CLAUDE.md import block and the sha256-marked policy copy in `AGENTS.override.md`.
- `scripts/zcode_activity.py` — read-only reader over ZCode's SQLite db (`~/.zcode/cli/db/db.sqlite`, `mode=ro`) → `SessionSummary` / `Activity`.
- `scripts/activity_cli.py` — terminal views (`runs/show/watch`); owns `ICONS`, `LABELS`, time formatting reused by the dashboard.
- `scripts/dashboard.py` + `scripts/dashboard.html` — `http.server` on 127.0.0.1:8765, GET-only: `/`, `/api/sessions?limit=N`, `/api/sessions/<id>/activity?after=<cursor>`. Single self-contained HTML page, inline CSS/JS, polling.
- `scripts/bridge_compat.py`, `zcode_bridge_launcher.py` — shim/launcher for the upstream coder-mcp-bridge (pinned ref in `manifest.json`).
- `scripts/doctor.py`, `context_report.py` — readiness checks, context-budget report.
- `policy/COMMANDER.md` — commander policy source; `templates/` — starters for `enable --with-templates`.
- Boundaries: the ZCode db is **never written**; the dashboard binds 127.0.0.1 only, rejects foreign Host headers, sends a strict CSP (no external scripts/fonts/CDN), and renders server text via `textContent` only. Scope (`DIR` / `--all`) comes from the command line, never from the page.
- External systems: ZCode Desktop 3.14 (db + MCP), Claude Code / Codex CLIs, GitHub releases (`get.ps1`).

## Stack and conventions

- Language/runtime: Python 3.10+ (dev machine 3.12), **standard library only**; PowerShell 5.1/7 for installers; vanilla HTML/CSS/JS (ES5-style, no build step) for the dashboard.
- Package manager: none — no third-party dependencies at runtime or in tests.
- Style: `from __future__ import annotations`, full type hints, dataclasses for records, small pure functions, comments only for non-obvious "why". Tests use `unittest` with fixtures built in temp dirs (see `tests/test_zcode_activity.py` `Fixture`). Conventional Commits.

## VERIFY — commands the reviewer runs on every worker result

Put these straight into each worker contract's VERIFY section, and run them yourself before you accept any result.

```text
install     (none — stdlib only)
test        python -m unittest discover -s tests
test (one)  python -m unittest discover -s tests -p "test_dashboard.py"
lint        python -m py_compile scripts/*.py
build       (none)
run         python scripts/zcrew.py dashboard --no-open   → http://127.0.0.1:8765/
```

Baseline 2026-09-27: 363 tests, OK (~15 s).

## Never change without asking the user

- The dashboard JSON API shape (`/api/sessions`, `/api/sessions/<id>/activity`) and `SessionSummary` / `Activity` fields — `zcrew runs/show/watch` share them.
- Security posture of the dashboard: 127.0.0.1 bind, Host check, CSP, GET-only, read-only db access.
- Adding any dependency (pip, npm, CDN, web fonts) — the project is stdlib-only and offline by design.
- `policy/COMMANDER.md`, `AGENTS.override.md` (sha256-marked, generated by `zcrew enable`), `manifest.json` versions, `get.ps1` / `scripts/install.ps1`.

## Delegation notes

- Workers read `AGENTS.md` in this repo. Keep the rules there, so each contract only has to describe the task.
- Parallel workers use `git worktree`s. They only see files that are committed, so commit `AGENTS.md` first.
- Model, reasoning level, worker count and correction budget come from `.claude/zcode-commander.json` if it exists, and from `~/.zcode-commander/config.json` otherwise.
